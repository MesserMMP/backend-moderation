# Модерация объявлений

ДЗ-1 по основам веб-разработки: HTTP API на FastAPI с проверкой входных данных и тестами.

## Запуск

Нужен Python 3.12 или новее. Из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
fastapi dev
```

В Windows окружение активируется командой `.venv\Scripts\activate`.
Сервис доступен на `http://127.0.0.1:8000`, Swagger UI — на `/docs`.
`GET /` возвращает `{"message": "Hello World"}`.

## Проверка объявления

`POST /predict` принимает JSON с семью обязательными полями:

| Поле | Тип | Проверка |
| --- | --- | --- |
| `seller_id` | `int` | Больше нуля |
| `is_verified_seller` | `bool` | Только JSON `true` или `false` |
| `item_id` | `int` | Больше нуля |
| `name` | `str` | Непустая строка после удаления пробелов по краям |
| `description` | `str` | Непустая строка после удаления пробелов по краям |
| `category` | `int` | Больше нуля |
| `images_qty` | `int` | Не меньше нуля |

Типы проверяются строго: строка `"1"`, дробь `1.5` и `true` не принимаются вместо целого числа. Лишние поля запрещены, чтобы опечатка в имени поля не осталась незамеченной. Положительные идентификаторы и непустые тексты — принятые в этом решении ограничения; перечень категорий в условии не задан, поэтому проверки по справочнику нет.

Ответ — одно JSON-значение: `true`, если найдены нарушения, и `false`, если нарушений нет.

| Продавец подтверждён | Количество изображений | Ответ |
| --- | --- | --- |
| Да | 0 или больше | `false` |
| Нет | 0 | `true` |
| Нет | 1 или больше | `false` |

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H 'Content-Type: application/json' \
  -d '{
    "seller_id": 1,
    "is_verified_seller": false,
    "item_id": 42,
    "name": "Велосипед",
    "description": "Городской велосипед, пробег 200 км",
    "category": 3,
    "images_qty": 0
  }'
```

Результат: HTTP 200, тело `true`. Если указать `"images_qty": 1`, тело ответа будет `false`.

## Ошибки

- **200** — проверка выполнена. Найденное нарушение тоже возвращается с 200: это результат проверки, а не ошибка запроса.
- **400** — пропущено поле, неверен тип или значение, переданы лишние поля либо повреждён JSON. Для ошибок валидации `detail` содержит список с полями `loc`, `msg`, `type`. Если тело нельзя декодировать, FastAPI возвращает текст причины в `detail`.
- **500** — неожиданная ошибка сервиса или репозитория. Клиент получает `{"detail": "Internal server error"}`, исключение записывается в серверный лог.

Ошибки валидации намеренно возвращаются с 400 вместо стандартного для FastAPI статуса 422 — так требует задание. OpenAPI описывает фактические статусы.

## Устройство проекта

```text
main.py                      создание приложения, обработка ошибок
models.py                    входная модель и модели ошибок
routers/predictions.py       HTTP-обработчик и получение зависимости
services/moderation.py       правило модерации
repositories/predictions.py  сохранение и чтение результата проверки
tests/                      тесты API, сервиса и репозитория
```

Обработчик передаёт проверенную модель сервису. Сервис вычисляет результат и сохраняет его через репозиторий. Повторный запрос с тем же `item_id` пересчитывается по новым данным и заменяет предыдущую запись.

Хранилище — словарь в памяти процесса, как локальное хранилище в семинаре. Оно теряет данные при перезапуске, не разделяется между процессами и растёт с количеством разных объявлений. Для учебного сервиса запускается один процесс; для постоянного хранения репозиторий нужно заменить реализацией с БД. Отдельного HTTP-метода для чтения истории в ДЗ нет.

## Проверки

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
python -m pytest --cov --cov-report=term-missing
ruff check .
ruff format --check .
```

Параметризованные тесты покрывают таблицу решений, обязательные поля, типы и границы значений, пустое и повреждённое тело запроса, повторную проверку объявления. Сбои сервиса и репозитория имитируются отдельно: API должен вернуть 500, а не результат модерации. Сервис тестируется с подменённым репозиторием; репозиторий — на сохранение, замену, изоляцию экземпляров и защиту сохранённой модели от изменения снаружи.
